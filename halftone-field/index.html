The grammar

ASCII art is usually a filter. Here each character is a material: one glyph carries several channels at once, and a page is a sequence of fields the same glyphs pass through.

Six channels per glyph

ChannelEncodesUsed on this page
PositionGeometry and contoursEvery scene is a target position field
SizeIntensity or depthPicks the glyph from a density ramp . : + * # @: elevation, compression at letter edges, closeness to content
SpacingDensity and compressionPiles along letter edges, clusters around the cards
OrientationDirection of movementMoving glyphs become - / | \ pointing along their path
OpacityUncertainty or disappearanceEvery glyph flickers between opacities; far terrain and strays in empty space go faint
MotionTransformation over timeScroll drives the morph; glyphs re-roll on their own clocks

How this page is built

  1. Lay a 45° screen of N glyphs across the viewport. Each glyph gets a permanent ID and a delay that sweeps left to right.
  2. Build each scene as a target field: N positions plus N sizes. Terrain and architecture are 3D; the field, the letters and the layout are flat and map one-to-one onto screen pixels.
  3. Match IDs to targets by strip-sorting both sets in screen space, so neighbours stay neighbours and the morph reads as one material moving.
  4. Interleave all five fields into one buffer: six vec4 attributes per glyph, uploaded once (and again on resize).
  5. In the vertex shader, mix field A into field B with a smoothstep per glyph. The blended size picks a character from the ramp, a hash of ID and time re-rolls it, and the fragment shader samples one 32-glyph atlas.

This prototype runs on WebGL 1 so it works almost everywhere. With WebGPU, the target fields could be generated in compute shaders instead of JavaScript, which removes the resize cost and lets the field grow past a million dots.
